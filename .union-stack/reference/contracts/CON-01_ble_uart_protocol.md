# [CON-01] BLE UART 메시지 계약

> **존재 이유 — 재사용 강제.** [PLAN-01a](펌웨어)와 [PLAN-01b](웹앱)는 형제이지 포함 관계가 아니다. 양쪽이 각자 메시지를 정의하면 반드시 어긋난다. **여기서 한 번만 정의하고 양쪽이 참조한다. 새로 만들면 결함이다.**
>
> **v0.2 — 메시지는 하나도 늘지 않았다.** 늘어난 것은 ① `LUX:` 전송 주기 ② "판정"의 범위 ③ 밤·아침의 유도 규칙, 셋 다 *기존 메시지의 해석*이다. 근거는 [WO-01b-4](표정 레이어).
>
> **v0.3 — 베개 IMU 실측 반영.** LSM6DSL 원시값은 개발 보정에만 쓰고, 제품 기록에는 사람의 뒤척임이 아닌 `베개 움직임 후보` 이벤트만 추가한다.
>
> **v0.4 — 아날로그 조도 센서로 교체.** P0.02(A0)의 12-bit ADC 상대값을 필터링해 기존 `LUX:` wire name으로 보낸다. 교정된 lux 단위가 아니며 이름은 RN/PWA 호환 때문에 유지한다.
>
> **v0.5 — issue #5 정합.** Pillow Node의 필수/미지원 명령을 분리하고, raw IMU 릴리스 기본 OFF·현재 상태 replay·LUX 실측 게이트를 명시한다. 근거 [ANL-01a].
>
> **v0.6 — 무선 촬영 트리거.** NU40은 휴대폰과 외부 컴퓨터 2개 central 연결을 허용한다. 컴퓨터가 NUS RX에 `FACE`를 쓰면 보드는 기존 `BTN:A:DOWN/UP`을 notify해 앱 얼굴을 연다.
>
> ※ 01 계보의 [PLAN-01a]·[PLAN-01b]는 `blast-radius`가 자동으로 잡고, 계보 밖 [PLAN-02f]·[CON-02f]·[WO-02f-1]은 frontmatter `consumers:`로 선언한다.

## 전송 계층
Nordic UART Service (NUS). 기존 배관은 `ref/toython-sleeppal/toython-sleeppal/code/`의 `toython_ble.ino`(보드)와 `web-client-index.html`(폰)에 이미 구현되어 있고 **검증 대상은 배관이 아니라 메시지다.**

```
Service  6e400001-b5a3-f393-e0a9-e50e24dcca9e
RX       6e400002-b5a3-f393-e0a9-e50e24dcca9e   폰 → 보드 (write)
TX       6e400003-b5a3-f393-e0a9-e50e24dcca9e   보드 → 폰 (notify)
```

- 인코딩: ASCII. **한 메시지 = 한 줄**, `\n`으로 구분. 수신 버퍼 64바이트.
- 광고 이름 `DEVICE_NAME`은 **반드시 팀 고유값으로 바꾼다.** 현재 스캐폴드는 `"TOYTHON-01"` 기본값이고, 참가자 100명이 모이면 이름이 충돌한다.

## 보드 → 폰 (TX, notify)
| 메시지 | 의미 | 주기 | 상태 |
|---|---|---|---|
| `HELLO` | 연결 직후 인사 | 1회 | 기존 |
| `BTN:<A\|B>:<DOWN\|UP>` | 버튼 이벤트 | 이벤트 | 기존 |
| `LUX:<정수>` | `4095 - 필터 ADC` 상대 밝기(0–4095, 밝을수록 큼). lux 단위 아님 | **5Hz · 데드밴드** | **v0.4** |
| `LUX:BASE:<정수>` | 기준선. 부팅 후 1회 + 재보정 시 | 이벤트 | **신규** |
| `STATE:<AWAKE\|DROWSY\|ASLEEP>` | 팰의 상태. **판정 주체는 보드다** | 전이 시 | **신규** |
| `SLEEPING` | System OFF 직전 마지막 통지. 이후 연결이 끊긴다 | 1회 | **신규** |
| `IMU:<seq>,<ax>,<ay>,<az>,<gx>,<gy>,<gz>` | LSM6DSL 원시 int16 6축. 개발 보정 전용 | 10Hz · 개발 빌드만 | **v0.3** |
| `MOVE:<seq>,<strength>,<duration_ms>` | 베개 움직임 후보. 사람의 자세·뒤척임 확정이 아님 | 이벤트 | **v0.3** |

### 베개 IMU — 원시 보정과 제품 이벤트를 분리
- LSM6DSL은 보드에서 50Hz로 읽는다. `IMU:`는 임계값을 만들기 위한 개발 빌드에서만 10Hz로 내리고 릴리스에서는 끈다.
- `MOVE:`는 1초 창의 가속도·자이로 에너지로 만든 후보이며 3초 refractory period를 둔다. `strength`는 0–255 내부 상대값, `duration_ms`는 후보 창 길이다.
- RN은 `MOVE:`만 수면 기록 저장소에 넘기고 WebView 얼굴에는 전달하지 않는다. `IMU:` 원시는 보정 세션 밖에서 영속 저장하지 않는다.
- 이 계약으로 `turn`, `left`, `right`, `sleep_stage`를 유도하면 결함이다. 베개를 손으로 옮기거나 보드가 내부에서 흔들린 경우를 사람의 뒤척임과 구분할 수 없기 때문이다.

### ⚠️ `LUX:` 전송 주기 — 5Hz, 데드밴드 적용
상태 판정에만 쓰인다면 1Hz도 충분하지만 폰 표정 반응은 1초 지연이 눈에 띈다. 아날로그 센서는 P0.02(A0)에서 12-bit로 50Hz 샘플링하고 EMA로 필터링한 뒤 5Hz로 내린다.

- **배선** — 센서 S → P0.02(A0/Arduino 2), `+` → VMOD 3.3V, `-` → GND. VBAT·VEXT·VBUS 금지.
- **5Hz**(200ms 간격) — ADC는 50Hz로 읽되 BLE에는 필터값만 보낸다.
- **데드밴드 8 counts** — 직전 전송값 대비 변화가 작으면 보내지 않는다. 어두운 방에서 BLE가 조용해진다.
- **극성 실측 완료** — 센서를 가리면 ADC가 약 2195→2675로 증가했다. wire 값은 `4095 - 필터 ADC`로 뒤집어 기존 PWA와 동일하게 밝을수록 커진다.
- **상대값** — 교정된 물리 lux가 아니므로 사용자에게 `lux` 단위로 표시하지 않는다.
- `LUX:`는 여전히 **사용자에게 수치로 노출되지 않는다**(규칙 3).

## 폰 → 보드 (RX, write)
| 메시지 | 의미 | 상태 |
|---|---|---|
| `LED:<0-255>` | LED 밝기 직접 지정. 디버그·폴백용 | 기존 |
| `TILT:<-90..90>` | 기울기 → 밝기 매핑. **P0에서 미사용** | 기존 |
| `SHAKE` | LED 3회 점멸. **P0에서 미사용** | 기존 |
| `WAKE` | 아침 전이 요청 | **신규** |
| `FACE` | 외부 컴퓨터 촬영 신호. 보드가 `BTN:A:DOWN`→`BTN:A:UP`으로 변환 | **v0.6 · 시연 전용** |

### 2중 central 시연 경로

```text
wake-face.sh → 컴퓨터 BLE central → NU40 NUS RX `FACE\n`
             → NU40 NUS TX `BTN:A:DOWN\nBTN:A:UP\n` → RN 앱
```

- 휴대폰이 첫 central로 계속 연결되고 notify를 구독한 상태에서 컴퓨터가 두 번째 central로 잠깐 연결한다.
- `FACE`는 사용자 데이터·인증·제품 원격제어가 아닌 촬영용 물리 버튼 대체다.
- 컴퓨터가 끊겨도 휴대폰 연결과 센서 notify는 유지돼야 한다.

### Pillow Node 지원 프로필

- 필수 TX: `HELLO`, `LUX`, `LUX:BASE`, `STATE`, `SLEEPING`, `MOVE`; 개발 전용 TX: `IMU`.
- 필수 RX: `WAKE`; 시연 전용 RX: `FACE`. `LED`, `TILT`, `SHAKE`는 데모 스캐폴드 명령이며 `NU40_Pillow_Node`에서는 **미지원**이다. 호출자는 Pillow 광고명에 이 셋을 릴리스 UI로 노출하지 않는다.
- `IMU:` 빌드 플래그는 기본 0이다. 보정 빌드만 명시적으로 1로 올리며, 런타임 기본값으로 대신하지 않는다.

## 유도 상태 — 밤·아침은 메시지가 없다
[IDENTITY]의 상태 6종 중 `밤`·`아침`을 나르는 `STATE:` 값이 없다. **메시지를 늘리지 않고 기존 신호에서 유도한다.**

| 눈 상태 | 진입 트리거 | 근거 |
|---|---|---|
| 각성 · 졸림 · 잠듦 | `STATE:AWAKE\|DROWSY\|ASLEEP` | 이 표 그대로 |
| **밤** | `SLEEPING` 수신 → 이후 연결 끊김은 **정상 종료** | 규칙 4 |
| **아침** | 밤 상태에서 `HELLO` 재수신(버튼 P0.11 기상 → 재광고) | [PHASE-01] System OFF 사양 |

## 호흡 주기 — 양쪽이 같은 숫자를 써야 한다
후광(보드)과 눈(폰)이 각자 주기를 정하면 **몸과 얼굴이 따로 논다.** [PLAN-01a]는 "빠르고 불규칙 / 느려지고 깊어짐 / 서서히 소등"이라는 질적 서술만 갖고 있었다 — 숫자를 여기서 한 번 정한다.

| 상태 | 주기 | 근거 |
|---|---|---|
| `AWAKE` | **4.0초** (15회/분) | 깨어 있는 안정 호흡 |
| `DROWSY` | **5.5초** (11회/분) | "느려지고 깊어짐" |
| `ASLEEP` | **6.5초** (9회/분) | 수면 호흡 |

**위상 0 = 마지막 `STATE:` 수신 시각.** 별도 동기 메시지를 두지 않는 대신 전이마다 재동기되므로 드리프트가 누적되지 않는다. 폰은 이 주기로 눈 높이를 ±2% 흔들고, 보드는 같은 주기로 후광을 흔든다.

## 계약 규칙
1. **상태 판정은 보드가 한다.** 여기서 *판정*이란 **`STATE:` 전이**를 말한다. 폰은 `STATE:`를 받아 눈을 바꿀 뿐, lux를 보고 스스로 상태를 옮기지 않는다. 판정 주체가 둘이면 무대에서 반드시 어긋난다.
   - 보드는 상태 전이 때뿐 아니라 BLE 연결 직후 현재 `STATE:` snapshot을 다시 보낸다. 폰 reload·재연결이 상태 전이를 기다리며 잘못 깨어 있으면 안 된다.
2. **표정 변조는 폰이 한다 — 단 상태 전이를 유발할 수 없다.** 폰은 `LUX:`를 읽어 눈부심 찡그림 같은 *연속적 표정*을 만들어도 된다(규칙 1의 "판정"에 해당하지 않는다). 이산 상태는 보드, 연속 표정은 폰 — 두 층은 합성되지 표를 덮어쓰지 않는다.
   - **폰은 glare 기준선을 자체 보유한다.** `LUX:BASE`는 초기 시드로만 쓰고, 이후에는 최근 30초 lux의 롤링 중앙값을 쓴다. 보드가 기준선을 재보정할 때 폰의 표정이 소리 없이 풀리는 결합을 끊기 위함이며, 결과적으로 규칙 1이 더 강하게 지켜진다.
   - **밤 상태에서 `LUX:` 응답은 0이다** — [ARCH-01] R4. 새벽에 누가 불을 켰다고 화면이 반응하면 이 제품이 막으려던 행동을 제품이 유발한다.
3. **`LUX:` 값을 사용자에게 노출하지 않는다** — [ARCH-01] R6(채점 금지). 디버그 화면에서만 본다. 찡그림은 수치가 아니라 형태이므로 노출이 아니다.
4. **`SLEEPING` 이후의 연결 끊김은 오류가 아니다.** System OFF는 리셋을 동반하므로 RAM도 BLE 연결도 사라진다. 폰은 이를 재연결 대상이 아니라 **정상 종료**로 처리한다 — 여기서 재연결을 시도하면 팰을 깨우는 그림이 된다.
5. **알 수 없는 메시지는 무시한다.** 양쪽 다 파싱 실패로 죽지 않는다(스캐폴드는 이미 그렇게 동작한다).
6. 메시지를 추가·변경하려면 **이 문서를 먼저 고치고** 양쪽을 맞춘다. 한쪽만 고치면 계약 위반이다.
7. **IMU 의미는 베개 움직임에 한정한다.** `MOVE:`를 사람의 뒤척임·자세·수면 단계로 사용자에게 단정해 표시하지 않는다.
8. **Pillow Node의 `LUX:` 동적 범위는 실측으로 문턱을 정한다.** wire 선형값을 임의 감마 변환하지 않는다. 정지 잡음과 의도 step이 분리되면 폰의 board source 문턱만 조정하고, 분리되지 않아 매핑을 바꿔야 하면 이 계약을 코드보다 먼저 버전업한다.

## 호출 예
```cpp
// 보드 (toython_ble.ino 의 sendLine 재사용) — 5Hz 데드밴드
char msg[24];
snprintf(msg, sizeof(msg), "STATE:%s", "DROWSY");
sendLine(msg);
```
```js
// 폰 (web-client-index.html 의 handleLine 확장)
const m = line.match(/^STATE:(AWAKE|DROWSY|ASLEEP)$/);
if (m) setEyeState(m[1]);                       // 이산 — 보드 소유
const l = line.match(/^LUX:(\d+)$/);
if (l) feedLux(+l[1]);                          // 연속 — 표정만, 전이 금지
```

## 검증 상태

`7de9e9b`와 [WO-02f-1]에서 `HELLO`·5Hz/deadband `LUX`·`LUX:BASE`의 NUS→RN 실기 수신은 확인됐다. `STATE`·`SLEEPING`·System OFF는 Pillow Node에 미구현이고, `LUX` 의도 step과 잡음 분포도 미측정이다. [WO-01a-2]가 남은 계약 사이클을 닫는다.
