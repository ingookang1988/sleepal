# Project History — strategic turning points

| Date | Turning point (fact) | Reason (why) | Implication |
|---|---|---|---|
| 2026-08-22 | 앱 방향을 **데모 얼굴 웹앱 → PWA 제품(놀이·내장 사운드·수면 트래커)**으로 확장하되, 스택은 **바닐라 팰 런타임 유지 + 트래커 기록 화면 한정 Vite+React + zero-dep 프록시**로 확정(Next.js 기각, 유튜브 뮤직은 제어 아닌 "공존", 뒤척임은 배게 IMU 로드맵) | PWA 요건(매니페스트·서비스워커·HTTPS)은 프레임워크와 무관하다. 팰 런타임은 rAF·센서·오디오 루프라 React 리렌더 모델과 어긋나고, 재작성 시 검증 자산(게이트 22/22 · [ADR-101]~[ADR-117])이 리셋된다. 얼굴과 트래커는 공유 코드가 거의 없어 React를 트래커 착수 시점에 도입해도 추가 비용이 0이다. LLM/STT 키는 클라이언트에 둘 수 없어 서버 프록시가 필수인데, 이미 있는 `scripts/serve.js`(Node fetch 내장, 의존성 0) 확장으로 충분해 Next.js API 라우트가 정당화되지 않는다. 유튜브 뮤직은 재생 제어 공개 API가 없다. 폰이 침대가 아닌 팰 안에 있어 가속도 기반 뒤척임 검출이 불가하다 | [PHASE-02]·[PLAN-02] 신설. 전면 프레임워크 전환 재제안 차단([ADR-302]). 배게 IMU 유닛이 로드맵에 재진입([PHASE-01]에서 범위 밖이던 베개 유닛) |
| 2026-08-21 | 폼팩터를 **폰 도크 → 폰 투입(윗면 슬롯)**으로 변경 | 도크 구조에서는 폰(163mm)이 창(164mm)을 거의 그대로 가려 후광이 상단 16mm 띠 하나로 줄었고(좌우 0.5mm), 폰 상단이 창 한복판이라 기댈 것이 트레이싱지뿐이었다. 투입 구조에서는 폰이 창을 가리는 대신 창 안에 들어앉아 화면 둘레 9mm가 전부 후광이 된다. 그리고 폰이 보이지 않게 되므로 "폰을 손에서 놓는다"는 제품 명제가 물리적으로 강해진다 | 외부 받침턱·걸림 립 폐기, 레일(받침 ㄷ자+앞 가이드+뒤 턱+정지 스토퍼)·액자형 확산지 도입. 투입 방향은 같은 날 윗면→우측 슬라이딩으로 재조정([DOM-01] v0.3 — 꺼내기 용이·윗면 온전). 정의서 §12의 발열 하향 근거("도크라 밀폐 인형보다 낮다")가 **무효** — 리스크 재평가 필요 |
| 2026-11-05 | 보드를 **선택 사항**으로 전환 — 폰 앱(PWA, 폰 Chrome 단독)만으로 "팰이 먼저 잠든다" 루프가 성립한다. 보드 미연결 시 폰의 모드 머신([CON-02] v0.2 규칙 4)이 눈 상태를 유도하고, 보드 연결 시에는 [CON-01] v0.5 규칙 1대로 보드가 판정한다 | 실물 펌웨어(`NU40_Pillow_Node`)는 `STATE:`·`SLEEPING`을 보내지 않아 폰 얼굴의 상태가 키·탭·데모로만 바뀌었고, 제품 명제의 물리적 근거(System OFF)가 실기에서 성립하지 않았다. [PLAN-02] §3·§5 는 이미 폰 쪽 판정(조도+수음 5분 히스테리시스)을 정의하고 있었으므로 새 판정 주체를 만든 것이 아니라 그 모드가 눈을 유도하게 한 것이다. 인간 지시 2026-11-05: "실제 작동하되 펌웨어보다 앱만으로" | [WO-02d-1] 착수(`mode.js`·`mode-core.mjs`·`face/mode-eyes.js`) — [ADR-401]. RN 앱([PLAN-02f])과 보드 경로는 유지되며 보드가 오면 판정 주체가 다시 보드다. 거치 자동 감지는 후속 WO(시작 버튼이 세션 시작) |
