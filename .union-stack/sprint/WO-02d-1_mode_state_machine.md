# [WO-02d-1] 모드 상태 머신

**선행 [WO-02a-2] · [CON-02] Draft 합의.** [PLAN-02] §3·§5 의 전환 조건을 구현한다. 눈 5상태(보드 소유)와 다른 층이다 — 모드는 폰이 소유하고, 표정·사운드가 [CON-02]로 구독한다.

## 목표
조도·수음 5분 히스테리시스 또는 명시 명령으로 4모드가 자동 전환되고, 전이가 [CON-02] 이벤트로 발행된다.

## 수용 기준
- [ ] `mode.js` (T 소유) — 단일 상태 보유 · 전이 규칙: 조도 낮음+무음 5분 → SLEEP · 조도 높음+소음 5분 → WAKE · `sleepIntent`([WO-02b-1]) → SLEEP · 기상 명령 → WAKE
- [ ] 수음 = 마이크 RMS 롤링(창·문턱은 상수로 노출, 실측 후 튜닝) · 조도 = 기존 lux 경로 재사용(카메라/보드, [ADR-110])
- [ ] 히스테리시스: 5분 창 안에서 조건이 깨지면 타이머 리셋 — 문턱 근처 진동으로 모드가 떨리지 않는다(눈 상태 머신과 같은 원리)
- [ ] 전이마다 [CON-02] `MODE:` 이벤트 발행 · 표정을 직접 조작하지 않는다(소비자가 알아서)
- [ ] 가상 시계 검사 경로(`?test`) — 5분을 기다리지 않고 전이 시나리오를 게이트로 검증([WO-01b-4] 방식)
- [ ] SLEEP 중 화면·발화·알림 0 — R4 는 모드 머신이 최종 집행자다

## 증거
가상 시계 시나리오 게이트(진입·이탈·리셋·명령 우선) 전부 통과 · 실기에서 불 끄고 5분 → SLEEP 전환 1회 실측.
