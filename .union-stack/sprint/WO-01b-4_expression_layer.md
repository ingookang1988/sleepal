# [WO-01b-4] 표정 레이어

**선행 [WO-01b-1].** b-1에 흡수하지 않는 이유 — b-1이 닫혀야 [WO-01b-2] 배포가 풀린다. 섞으면 배포가 표정 완성도에 인질로 잡힌다. 파일이 하나라 재배포는 공짜다: **b-1 → 배포 → 표정 얹고 재배포.**

**그리고 지금 아니면 못 넣는다** — [PHASE-01]이 15:40 이후 기능 추가를 금지하고, 얼굴은 현장에서 만들 수 없다.

## 목표
상태(이산·보드 소유) 위에 **표정(연속·환경 구동)**을 합성한다. 표정 채널이 전부 0이면 b-1의 5상태와 픽셀 단위로 동일하다 — 순수 추가이며, 죽어도 b-1이 남는다.

## 수용 기준
- [ ] 눈 프리미티브 `<circle>` → `<rect rx>` — 보이는 결과 동일, 높이·모서리·기울기가 독립 제어된다
- [ ] **glare 채널** — `glare = clamp(log((lux+1)/(base+1)) / log(16), 0, 1)`. base는 **폰 자체 롤링 중앙값 30초**([CON-01] 규칙 2)
- [ ] **비대칭 시상수 — 상승 0.15초 / 하강 2.5초.** 대칭이면 슬라이더로 보이고 비대칭이어야 반응으로 보인다. 이 레이어의 핵심은 최종 형태가 아니라 이 두 숫자다
- [ ] **움찔** — lux 2스톱 급등 시 하드 블링크 0.09초 + 25% 과도 찡그림 후 정착
- [ ] **안도** — glare 급락 시 느린 부드러운 깜빡임 1회 + 눈이 5% 가라앉음. **큐시트 30초의 핵심 표정이다**
- [ ] 기하 매핑: 눈 높이 45→17.1 · `rx` = h/2 · 중심 Y 36.5→35.0 · **눈꼬리 안쪽 끝 7° 내림**(왼눈 +7°, 오른눈 −7°). 기울기가 없으면 찡그림이 아니라 졸린 눈이다
- [ ] **상태 게이팅** — 각성 100% · 졸림 100%(눈꺼풀과 합성) · 잠듦 미세 떨림만(±0.25mm, 눈 다시 안 뜸) · **밤 0** · 아침 50%(기지개 중 억제)
- [ ] **미세 표정 3종** — B 미세 표류(각성 시 두 눈 함께 ±0.4mm, 주기 ~4초) · D 좌우 비대칭(졸림에서 한쪽 3~5% 더 내림) · E 무거워지는 깜빡임(**뜨는** 속도를 늦춘다)
- [ ] 호흡 동기 C — 눈 높이 ±2%. `STATE:` 수신 시각을 위상 0으로 재동기. **독립 항목이라 빼도 나머지 멀쩡**
- [ ] 단일 `requestAnimationFrame` 루프 + 지수 평활. **라이브러리 0** ([PLAN-01b] 제약). 배경색 전이만 CSS에 남긴다
- [ ] `?demo=1`에서 **보드 없이 glare 이벤트를 합성** — 리허설에서 표정을 확인할 수 있어야 한다
- [ ] **표정이 상태 전이를 유발하지 않는다** ([CON-01] 규칙 2)

## ⛔ R4 하드 게이트
**밤 상태에서 glare 응답이 0이 아니면 [ARCH-01] R4 위반이다.** 새벽 3시에 누가 불을 켰다고 화면이 반응하면, 이 제품이 막으려던 바로 그 행동을 제품이 유발한다.
→ 스위치가 아니라 **`if (state === NIGHT) return;`을 표정 루프 최상단**에 둬 계산 자체가 돌지 않게 한다.

## 규범 검토 (통과 근거)
- **R2** — [ARCH-01] R2의 예시가 이미 "팰이 눈부셔서 눈을 못 감고 있어요"다. 찡그림은 그 문장의 **언어 이전 버전**이고 R1(말하지 않는다)의 이행이다
- **R6** — 찡그림은 수치가 아니고 전일 대비 비교가 불가능하다. 후광이 이미 나르는 정보를 얼굴이 나눠 가질 뿐
- **R5** — "시무룩해지거나 삐질 수는 있어도"가 명시적으로 허용한다

## 증거
계단 입력에 대한 glare 반응 곡선 로그(상승 0.15s / 하강 2.5s 확인) · `?demo=1` 눈부심→안도 시퀀스 캡처 · 밤 상태 `LUX:` 폭주 주입 시 눈 기하 변화량 0 · 표정 루프 동작 중 상태 전이 호출 0회.

## 보드 없이 표정 보기 — 조도 대역 3종 (디버그 화면)

**폰 자체 조도 센서는 답이 아니다.** `AmbientLightSensor` 는 크롬에서 플래그(`#enable-generic-sensor-extra-classes`) 없이 안 열리고(측정: `false`), **무엇보다 폰이 몸통 안에 들어가면 방이 아니라 골판지 안쪽을 본다.** 최종 시연의 lux 는 반드시 보드에서 온다.

손에 들고 반응을 볼 때만 쓰는 세 경로를 디버그 화면(세 손가락 탭)에 넣었다. **셋 다 `feedLux()`/`GL.raw` 로만 들어가 [CON-01] 규칙 2 는 그대로다.**

| 경로 | 쓰임 | 신뢰도 |
|---|---|---|
| **glare 슬라이더** | 상수 튜닝(0.62 · 7°). lux 체인을 건너뛴다 | 결정적 |
| **불 켜기 / 끄기** | 체인 전체(기준선·움찔·안도) | 결정적 |
| **카메라 조도계** | "살아있어 보이는가" | ⚠ 트랜지언트만 |

### ⚠ 카메라의 자동 노출
카메라는 밝아지면 스스로 어둡게 찍는다 — AE 가 잡히고 나면 평균 휘도가 거의 그대로라 **절대 조도를 못 잰다.** 다만 AE 가 잡히기까지 0.5~1초의 스파이크는 진짜고, 이 레이어는 전부 트랜지언트 기반(움찔 0.15초 · 30초 롤링 중앙값)이라 **움찔·안도는 제대로 보인다.** 정상상태 찡그림 깊이는 슬라이더로 볼 것. `exposureMode: 'manual'` 을 시도하고 되면 로그에 남긴다.

R7 준수 — 프레임을 32×24 평균 휘도 하나로 줄여 즉시 버린다. 저장·전송하지 않고 인체·자세를 보지 않는다. [ARCH-01] R7 이 "조도계 이외의 용도로 읽지 않는가"라고 써 조도계 용도를 명시적으로 허용하며, [PLAN-01a] 의 BH1750 미확보 폴백이 이미 이 경로다.

슬라이더 1.00 → 높이 17.06 · 상태 불변 · 5초 뒤 40.41 로 복귀(τ=2.5 곡선) · 불 켜기 움찔 발화 후 17.43 · 불 끄기 안도 발화, 150ms 19.05(거의 안 풀림) → 2500ms 34.39 · 전 구간 `F.state` 불변 · R3 얼굴 문자 0 유지.

## dev 화면 — 조도가 실제로 들어오고 있는지 확인하는 계기판

대기 화면에 **`dev` 버튼**을 넣었다(기존 세 손가락 탭도 유지). 10Hz 로 갱신한다.

**핵심은 큰 숫자가 아니라 `age` 와 `n` 이다.** lux 숫자만 보면 *빛이 일정한 것*과 *아예 안 읽고 있는 것*이 구분되지 않는다 — 둘 다 숫자가 멈춰 있다. 마지막 표본 이후 경과(`age`)와 누적 표본 수(`n`)가 그걸 가른다. 1초 넘게 안 들어오면 주황색으로 바뀐다.

| 표시 | 무엇 |
|---|---|
| 큰 숫자 | 현재 lux |
| **`age`** | 마지막 표본 이후 경과. **1초 넘으면 주황** = 안 들어오는 중 |
| **`n`** | 누적 표본 수. 안 오르면 경로가 죽은 것이다 |
| `src` | `board` · `camera` · `sim` · `slider — lux 우회` |
| 스파크라인 | 최근 30초 lux(로그). 점선 = 기준선(중앙값). 오른쪽 끝 점이 초록이면 살아 있고 주황이면 멎었다 |
| 막대 2개 | `glare raw`(목표) vs `now`(평활). **비대칭 시상수가 눈에 보인다** — 올라갈 땐 붙어 움직이고 내려올 땐 now 가 뒤처진다 |

`camera ON` 일 때는 **평균휘도 x/255 원값**도 같이 보여준다 — 자동 노출이 물고 있는지 여기서 드러난다.

R3 유지 — dev 화면은 얼굴을 **덮지 않고 대체한다**(검사에서 `faceHidden: true`).

수신 없음 → `age —  수신 없음` + 주황 · 표본 주입 후 `age 0.48s n=16` 초록 · 1.2초 방치 후 `age 2.47s` 다시 주황 · 스파크라인 435픽셀 렌더 · 시트 14/14 유지.

## ADR 번호 대역 (2026-08-22)
이 계보의 원장 항목은 **101–111**이다. 43–58 에서 이관했다 — 몸통 세션과 병렬로 돌다 `ADR-49`~`ADR-53` 을 양쪽이 동시에 할당해 다섯 개 id 가 두 결정씩 가리켰다. 이후 얼굴 ADR 은 **112부터**. 규범은 [ARCH-00] §ADR bands, 결정 자체는 [ADR-301].

## 표정 HUD — 얼굴을 보면서 수치를 읽는다 (2026-08-22)

**왜 필요했나.** 디버그 화면은 얼굴을 *대체*한다([ADR-107] · R3). 그래서 숫자를 보거나 얼굴을 보거나 둘 중 하나였고, "카메라를 켰는데 아무 반응이 없다"가 **경로가 죽은 것인지 glare 가 정말 0 인 것인지 구분되지 않았다.** HUD 는 그 둘을 한 화면에 놓는다. 결정은 [ADR-112].

`얼굴 하단 띠` · 4줄 · 10Hz. 대기 화면 `dev` → **표정 HUD** 버튼, 또는 `?dev=1`.

| 줄 | 내용 |
|---|---|
| 1 | 상태 · gate · `src` · **`age`/`n`**(살아 있는가 — [ADR-111]) · fps |
| 2 | `lux` · **`base`** · `raw` · `now` · `cam x/255` + raw/now 막대 2개 |
| 3 | `g` · **`h`**(눈 높이) · `cy` · `tilt` · `lid` · `blk` |
| 4 | `drift` · `breath` · `settle` · `tremor` · **움찔/안도 경과** |

**`base` 를 2줄에 올린 것이 이번 계측의 핵심이다.** raw 가 왜 0 인지는 lux 만 봐서는 알 수 없고 base 와 나란히 놓아야 드러난다.

### ⛔ 규범 — 기계로 못박은 것
- **R3** — HUD 는 `#faceScreen` **바깥의 형제**다. 처음에 안에 뒀다가 시트의 "얼굴 문자 0" 게이트에 잡혔다(textContent 164). 띠의 위 경계는 CSS 상수가 아니라 매 프레임 눈 바운딩박스에서 계산한다(`EYE_SAFE = 61mm`)
- **R4** — `NIGHT` 이면 `devMode` 와 무관하게 강제로 사라진다. 밤에 lux 를 5↔9000 으로 퍼부어도 다시 켜지지 않는다
- **무대 유출 차단** — 기본 OFF · `sessionStorage` 라 탭을 닫으면 죽는다

### 검사 — `app/face-sheet.html` **18/18**(기존 14 + HUD 4)
`R3 HUD 가 얼굴 밖` · `HUD 기본 OFF` · `R3 HUD ∩ 눈 = 0`(간격 29.8px, **가장 찡그린 상태에서 측정**) · `⛔ R4 밤 HUD 0`(devMode 는 켜진 채인데 HUD 만 사라진다).

## 카메라 조도계가 실시간으로 안 보이던 것 — 원인 (2026-08-22)

**경로는 죽어 있지 않았다.** 계측 결과 `n` 은 증가하고 lux·평균휘도도 갱신되고 있었다. 문제는 **`base`** 다.

자동 노출이 평균 휘도를 붙들면 30초 롤링 중앙값([ADR-103])이 신호를 그대로 따라와 `base ≈ v` 가 되고 `log((v+1)/(base+1))` 이 영구히 0 이다. **glare 가 0 이니 얼굴이 반응할 이유가 없다.** [ADR-110]이 적어둔 "AE 때문에 절대 조도를 못 잰다"의 *구체적 귀결*이 이것이다.

| | lux | base | raw | 눈 높이 |
|---|---|---|---|---|
| AE 물린 상태 | 952 | 935 | **0.006** | 45.72 (무반응) |
| 기준선 고정 후 밝힘 | 2930 | 935 (고정) | **0.412** | **33.62** · tilt 2.88° |

→ 디버그 화면에 **기준선 고정** 버튼을 넣었다([ADR-113]). 지금 중앙값에 base 를 묶어 그 뒤의 변화가 raw 로 나타나게 한다. **절대 조도가 생기는 것은 아니다** — dev 전용이고 보드 경로에는 쓰지 않으므로 [ADR-103]·[CON-01] 규칙 2 는 불변이다.

## "눈이 감기는 건 되는데 떠지는 건 안 된다" — 원인 조사 (2026-08-22)

계측으로 넷을 갈랐다. **결정적 원인은 설계값 자체(TAU_DOWN)이고, 그 위에 하드 버그 1건이 있었다.**

### ① 하드 버그 — `dt < 0` 이면 평활기가 발산한다 → **수정함** [ADR-114]
`smooth()` 는 `tgt + (cur−tgt)·exp(−dt/τ)` 다. `dt` 가 음수면 계수가 1 을 넘어 **목표에서 멀어지는 방향으로 증폭**한다. 조사 중 하네스에서 재현됐다 — `GL.now` **233.9**, `g` 가 1.25 에 고정, 눈 높이 **9.9mm 에서 영구히 안 떠짐**. 정확히 신고된 증상이다.
`Math.min(t−last, 0.1)` → `clamp(t−last, 0, 0.1)`. rAF 타임스탬프는 단조증가라 **폰 실기 경로에서는 재현을 확인하지 못했다** — 그래도 한 줄 방어이고, 검사 경로(`SP._step`)는 임의 시각을 넣으므로 **이 WO 의 시상수 증거 자체가 발산에 노출돼 있었다.** 클램프 후 상수 불변(아래).

### ② 결정적 원인 — 비대칭이 30:1 이다 (설계값, **인간 판단 필요**)
| | 시간 |
|---|---|
| 찡그리기 (τ=0.15) | **0.15초** |
| 눈 90% 회복 | **4.3초** |
| 눈 99% 회복 | **8.4초** |

여기에 **카메라는 자극 자체가 1초 미만의 AE 트랜지언트**([ADR-110])다. 그래서 실제로 보이는 그림은 *한순간 찡그리고 10초 동안 천천히 풀리는* 것이고, 손에 들고 흔들어 보는 사람에게는 **"안 떠진다"로 읽힌다.** 슬라이더·불켜기 버튼은 자극이 지속되므로 이 대비가 드러나지 않는다.
τ 두 개는 이 레이어의 정의 그 자체라(§실측된 시상수) **임의로 바꾸지 않았다.** 결정 필요.

### ③ 기여 원인 — 안도 깜빡임이 *닫는* 것으로 시작한다
빛이 떨어지는 순간 `안도`가 발화하고 봉투 `[0.45, 0.15, 0.75]` 로 **눈이 완전히 감긴다**(실측 `blk` 1.00 @ +0.6s) — 뜨기 시작하는 건 그 뒤다. 즉 불을 치웠을 때 **처음 보이는 동작이 "더 감김"**이다. 의도된 연출이지만 ②와 겹치면 "안 떠진다"를 강화한다.

### ④ 배제됨 — 잡음 정류(ratchet)
비대칭 평활기는 잡음 입력에서 평균이 아니라 **상단 포락선**에 붙는다(원리 확인: 평균 raw 0.005 인 스파이크 열에서 `now` 0.071 — 14배). 그러나 카메라 실제 규모로는 작다. 장면 고정 · 60초 · 5Hz:

| 평균휘도 흔들림 | ±1 | ±3 | ±6 | ±12 | ±25 |
|---|---|---|---|---|---|
| 눈 뜸 | 100% | 99% | 98% | 97% | **94%** |

최악 ±25 에서도 6% 다. **이것 때문에 안 떠지는 것은 아니다.**

### 배제됨 — 기준선 추종
급락 시 `base` 가 이전 밝은 값이면 `raw = clamp(음수, 0, 1) = 0` 이라 오히려 즉시 열림 목표가 된다. 계단 하강 실측: h 21.7 → 33.3(1.6s) → 43.2(5.6s) → 44.1(10.6s) — **닫힌 채 머무르지 않는다.**

### 클램프 후 시상수 재실측 — 전부 불변
상승 150ms **0.63**(1−1/e) · 상승 1s 0.999 · 하강 150ms **0.948** · 하강 2500ms **0.37**(1/e). 시트 **18/18** 유지.

## 놓아줌 — 빛이 지면 반응으로 눈이 다시 떠진다 (2026-08-22) [ADR-115]

인간 결정: **"조도에 따라서 다시 뜨는 동작은 필요하다."**

`TAU_DOWN` 을 깎지 않았다. 위 §원인 조사 ②가 지목한 진짜 문제는 시상수가 아니라 **사건 구조의 비대칭**이었다 — 오를 때는 움찔이라는 능동 제스처가 있고, 질 때는 안도가 *닫는 것으로 시작*한 뒤 뜨는 일을 수동 감쇠에 맡겼다.

→ **안도가 발화한 동안에만** 짧은 시상수로 놓아준다. `TAU_RELEASE = 0.4` · 창 `RELEASE_T = 1.35`(= 안도 깜빡임 봉투 0.45+0.15+0.75 전체). 눈꺼풀이 다시 열리는 그 순간에 찡그림도 이미 풀려 있게 맞춘 길이다.

| | 이전 | 이후 |
|---|---|---|
| 급락(안도 발화) 1초 뒤 | 21.7mm 근처 | **43.2mm · 96%** |
| 급락 99% 회복 | 8.4초 | **~1초** |
| 완만 하강 1초 뒤 | — | 76% (**τ 2.5 유지**) |

**완만한 하강은 건드리지 않았다.** 배경 이완의 느림은 그대로이고, 안도는 여전히 큐시트 30초의 핵심 표정으로 남는다. 놓아줌 창 안에서 눈꺼풀 깜빡임과 찡그림 해제가 동시에 돈다 — 실측 `blk` 0.44@0.2s · 0.73@0.6s · 0@1.0s, 같은 구간에서 `now` 0.829 → 0.025.
