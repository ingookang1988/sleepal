# [WO-01b-4] 표정 레이어

**선행 [WO-01b-1].** b-1에 흡수하지 않는 이유 — b-1이 닫혀야 [WO-01b-2] 배포가 풀린다. 섞으면 배포가 표정 완성도에 인질로 잡힌다. 파일이 하나라 재배포는 공짜다: **b-1 → 배포 → 표정 얹고 재배포.**

**그리고 지금 아니면 못 넣는다** — [PHASE-01]이 15:40 이후 기능 추가를 금지하고, 얼굴은 현장에서 만들 수 없다.

## 목표
상태(이산·보드 소유) 위에 **표정(연속·환경 구동)**을 합성한다. 표정 채널이 전부 0이면 b-1의 5상태와 픽셀 단위로 동일하다 — 순수 추가이며, 죽어도 b-1이 남는다.

## 수용 기준
- [ ] 눈 프리미티브 `<circle>` → `<rect rx>` — 보이는 결과 동일, 높이·모서리·기울기가 독립 제어된다
- [ ] **glare 채널** — `glare = clamp(log((lux+1)/(base+1)) / log(16), 0, 1)`. base는 **폰 자체 롤링 중앙값 30초**([CON-01] 규칙 2)
- [ ] **비대칭 시상수 — 상승 0.15초 / 하강 2.5초.** 대칭이면 슬라이더로 보이고 비대칭이어야 반응으로 보인다. 이 레이어의 핵심은 최종 형태가 아니라 이 두 숫자다
- [ ] **움찔** — lux 2스톱 급등 시 하드 블링크 0.09초 + 25% 과도 찡그림 후 정착
- [ ] **안도** — glare 급락 시 느린 부드러운 깜빡임 1회 + 눈이 5% 가라앉음. **큐시트 30초의 핵심 표정이다**
- [ ] 기하 매핑: 눈 높이 45→17.1 · `rx` = h/2 · 중심 Y 36.5→35.0 · **눈꼬리 안쪽 끝 7° 내림**(왼눈 +7°, 오른눈 −7°). 기울기가 없으면 찡그림이 아니라 졸린 눈이다
- [ ] **상태 게이팅** — 각성 100% · 졸림 100%(눈꺼풀과 합성) · 잠듦 미세 떨림만(±0.25mm, 눈 다시 안 뜸) · **밤 0** · 아침 50%(기지개 중 억제)
- [ ] **미세 표정 3종** — B 미세 표류(각성 시 두 눈 함께 ±0.4mm, 주기 ~4초) · D 좌우 비대칭(졸림에서 한쪽 3~5% 더 내림) · E 무거워지는 깜빡임(**뜨는** 속도를 늦춘다)
- [ ] 호흡 동기 C — 눈 높이 ±2%. `STATE:` 수신 시각을 위상 0으로 재동기. **독립 항목이라 빼도 나머지 멀쩡**
- [ ] 단일 `requestAnimationFrame` 루프 + 지수 평활. **라이브러리 0** ([PLAN-01b] 제약). 배경색 전이만 CSS에 남긴다
- [ ] `?demo=1`에서 **보드 없이 glare 이벤트를 합성** — 리허설에서 표정을 확인할 수 있어야 한다
- [ ] **표정이 상태 전이를 유발하지 않는다** ([CON-01] 규칙 2)

## ⛔ R4 하드 게이트
**밤 상태에서 glare 응답이 0이 아니면 [ARCH-01] R4 위반이다.** 새벽 3시에 누가 불을 켰다고 화면이 반응하면, 이 제품이 막으려던 바로 그 행동을 제품이 유발한다.
→ 스위치가 아니라 **`if (state === NIGHT) return;`을 표정 루프 최상단**에 둬 계산 자체가 돌지 않게 한다.

## 규범 검토 (통과 근거)
- **R2** — [ARCH-01] R2의 예시가 이미 "팰이 눈부셔서 눈을 못 감고 있어요"다. 찡그림은 그 문장의 **언어 이전 버전**이고 R1(말하지 않는다)의 이행이다
- **R6** — 찡그림은 수치가 아니고 전일 대비 비교가 불가능하다. 후광이 이미 나르는 정보를 얼굴이 나눠 가질 뿐
- **R5** — "시무룩해지거나 삐질 수는 있어도"가 명시적으로 허용한다

## 증거
계단 입력에 대한 glare 반응 곡선 로그(상승 0.15s / 하강 2.5s 확인) · `?demo=1` 눈부심→안도 시퀀스 캡처 · 밤 상태 `LUX:` 폭주 주입 시 눈 기하 변화량 0 · 표정 루프 동작 중 상태 전이 호출 0회.

## 진행 (2026-08-22)

### 실측된 시상수 — 이 레이어의 핵심
루프를 결정적으로 밟아(`SP._step`) 계단 입력에 대한 응답을 측정했다.

| | 실측 | 기대 |
|---|---|---|
| 150ms 상승 | **0.632** | 1−1/e = 0.632 (τ=0.15) |
| 1s 상승 | 0.999 | 포화 |
| 150ms 하강 | **0.942** | 거의 안 내려간다 |
| 2500ms 하강 | **0.368** | 1/e = 0.368 (τ=2.5) |

**비대칭이 숫자로 증명됐다.** 같은 150ms 동안 올라갈 땐 63%, 내려올 땐 6%만 움직인다.

### 기하 매핑 실측
높이 45.07 → **17.13** · 모서리 8.56 = 높이/2 · 중심 Y **35.01** · 눈꼬리 **+7.00 / −7.00**.

### ⛔ R4 하드 게이트 — 통과
밤 상태에서 lux 를 5↔9000 으로 40회 진동시키고 120프레임을 밟았다.
**눈 기하·기울기·감긴눈 transform 이 전부 문자열 단위로 동일**, `GL.now/flinch/relief` 전부 0. `expression()` 최상단의 `if (F.state === 'NIGHT') return null;` 이 계산 자체를 막는다.

### [CON-01] 규칙 2 — 표정은 상태를 옮기지 않는다
lux 10샘플 + 40샘플 주입, 계단·진동 전 구간에서 `F.state` 불변 확인.

### 그 외 확인
잠듦에서 밝은 빛에 **눈을 다시 뜨지 않는다**(높이 불변, 떨림 0.69mm p-p) · 아침 게이트 0.5(높이 30.55 vs 각성 17.28) · 좌우 비대칭 0.550/0.572 · 호흡 주기 [CON-01] 표와 일치.

### 눈꺼풀을 곡선으로 바꿨다 (WO 범위 밖 추가 1건)
b-1 시트에서 **직선 아랫변이 뜬 눈을 사발처럼 잘라** 기계로 보였다. 졸림은 이 제품에서 가장 중요한 상태이고([PLAN-01b] 목표가 "10m 뒤에서 졸려 한다가 읽혀야 한다") 여기서 가장 크게 드러난다. → `<rect>` → `<path>`, 아랫변 가운데가 3mm 더 내려온다.

## 보드 없이 표정 보기 — 조도 대역 3종 (디버그 화면)

**폰 자체 조도 센서는 답이 아니다.** `AmbientLightSensor` 는 크롬에서 플래그(`#enable-generic-sensor-extra-classes`) 없이 안 열리고(측정: `false`), **무엇보다 폰이 몸통 안에 들어가면 방이 아니라 골판지 안쪽을 본다.** 최종 시연의 lux 는 반드시 보드에서 온다.

손에 들고 반응을 볼 때만 쓰는 세 경로를 디버그 화면(세 손가락 탭)에 넣었다. **셋 다 `feedLux()`/`GL.raw` 로만 들어가 [CON-01] 규칙 2 는 그대로다.**

| 경로 | 쓰임 | 신뢰도 |
|---|---|---|
| **glare 슬라이더** | 상수 튜닝(0.62 · 7°). lux 체인을 건너뛴다 | 결정적 |
| **불 켜기 / 끄기** | 체인 전체(기준선·움찔·안도) | 결정적 |
| **카메라 조도계** | "살아있어 보이는가" | ⚠ 트랜지언트만 |

### ⚠ 카메라의 자동 노출
카메라는 밝아지면 스스로 어둡게 찍는다 — AE 가 잡히고 나면 평균 휘도가 거의 그대로라 **절대 조도를 못 잰다.** 다만 AE 가 잡히기까지 0.5~1초의 스파이크는 진짜고, 이 레이어는 전부 트랜지언트 기반(움찔 0.15초 · 30초 롤링 중앙값)이라 **움찔·안도는 제대로 보인다.** 정상상태 찡그림 깊이는 슬라이더로 볼 것. `exposureMode: 'manual'` 을 시도하고 되면 로그에 남긴다.

R7 준수 — 프레임을 32×24 평균 휘도 하나로 줄여 즉시 버린다. 저장·전송하지 않고 인체·자세를 보지 않는다. [ARCH-01] R7 이 "조도계 이외의 용도로 읽지 않는가"라고 써 조도계 용도를 명시적으로 허용하며, [PLAN-01a] 의 BH1750 미확보 폴백이 이미 이 경로다.

## dev 화면 — 조도가 실제로 들어오고 있는지 확인하는 계기판

대기 화면에 **`dev` 버튼**을 넣었다(기존 세 손가락 탭도 유지). 10Hz 로 갱신한다.

**핵심은 큰 숫자가 아니라 `age` 와 `n` 이다.** lux 숫자만 보면 *빛이 일정한 것*과 *아예 안 읽고 있는 것*이 구분되지 않는다 — 둘 다 숫자가 멈춰 있다. 마지막 표본 이후 경과(`age`)와 누적 표본 수(`n`)가 그걸 가른다. 1초 넘게 안 들어오면 주황색으로 바뀐다.

| 표시 | 무엇 |
|---|---|
| 큰 숫자 | 현재 lux |
| **`age`** | 마지막 표본 이후 경과. **1초 넘으면 주황** = 안 들어오는 중 |
| **`n`** | 누적 표본 수. 안 오르면 경로가 죽은 것이다 |
| `src` | `board` · `camera` · `sim` · `slider — lux 우회` |
| 스파크라인 | 최근 30초 lux(로그). 점선 = 기준선(중앙값). 오른쪽 끝 점이 초록이면 살아 있고 주황이면 멎었다 |
| 막대 2개 | `glare raw`(목표) vs `now`(평활). **비대칭 시상수가 눈에 보인다** — 올라갈 땐 붙어 움직이고 내려올 땐 now 가 뒤처진다 |

`camera ON` 일 때는 **평균휘도 x/255 원값**도 같이 보여준다 — 자동 노출이 물고 있는지 여기서 드러난다.

R3 유지 — dev 화면은 얼굴을 **덮지 않고 대체한다**(검사에서 `faceHidden: true`).
