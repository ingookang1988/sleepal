# TOYTHON 2026 — 슬립팰 (SleepPal)

2026년 8월 21일, 토이톤 해커톤 D-1에 정리된 자료 일체.
행사 분석 → 시장 조사 → 제품 기획 → 제작 도면까지의 전 과정과 원본 자료.

---

## 지금 확정된 것

> **슬립팰은 사용자보다 먼저 졸려 하고 먼저 잠드는 반려 수면등이다.**
> 사용자는 팰을 재우기 위해 방을 어둡고 조용하게 만들고, 잠들기 전 자신의 폰을
> 팰에게 올려놓아 얼굴을 빌려준다. 그 과정에서 자신이 잠들 준비를 마친다.

| 항목 | 확정 |
|---|---|
| 카테고리 | 반려 수면등 (정체성=반려, 명분=수면) |
| 폼팩터 | 가로형 몸통 200 × 130 × 65mm + 폰 도크 |
| 얼굴 | 폰 화면 (가로 전체화면, 눈만) |
| 몸 | LED 4개 + 확산지 = 후광 호흡 |
| 소리 | 폰 스피커 — 숨소리 · 하품 (말은 하지 않음) |
| 센싱 | 조도(BH1750) + 마이크. **카메라 인체 감지 배제** |
| 전력 | 잠들면 nRF52840 System OFF |
| 기반 자산 | quiet space (혼잣말 → 텍스트, 이미 구현됨) |

**한 줄** — *수면등은 제가 끕니다. 팰은 자기가 잠듭니다.*

파일은 전부 HTML입니다. 브라우저로 열면 됩니다. 온라인 링크는 항상 최신본입니다.

### 01_product-spec-v1.1.html — **제품 정의서**
가장 중요한 문서. §1~§14로 구성. 정의 · 문제 · 핵심 원리 · 포지셔닝 · 3층 구조 ·
상태 모델(6단계 순환도) · 하드웨어 · 소프트웨어 · **설계 규율 8개** · 하지 않는 것 ·
차별화 · 리스크 · 로드맵 · 미정 사항.
→ https://claude.ai/code/artifact/629a8044-d068-4cc6-92c7-ccf4571dac12

**§9 설계 규율 8개**가 이 문서의 심장입니다. 위반하면 제품이 무너지는 규칙이고,
카피 검수와 코드 리뷰 기준으로 그대로 씁니다.

1. 팰은 말하지 않는다
2. 앱에 2인칭 문장을 쓰지 않는다
3. 눈 영역에 문자를 띄우지 않는다
4. 밤에는 아무것도 하지 않는다
5. 팰은 죽지 않는다
6. 수면을 채점하지 않는다
7. 방을 재되 사람을 보지 않는다
8. 네트워크 없이도 살아 있다

**타임박스의 시간 배분, 큐시트 골격, 폴백 표는 그대로 유효합니다.**

## code/ — 코드 3종

| 파일 | 용도 | 상태 |
|---|---|---|
| `toython_ble.ino` | 보드 BLE UART 양방향 스캐폴드. 버튼 이벤트 송신, LED/명령 수신 | 컴파일 검증 필요 |
| `pin_finder.ino` | 버튼·LED 아두이노 핀 번호 찾기. 보드 받고 30초 | 현장용 |
| `web-client-index.html` | Web Bluetooth 클라이언트. 폰 IMU↔보드 LED 양방향 루프, Wake Lock 포함 | Vercel 배포 필요 |

**주의** — `web-client-index.html`은 BLE 배관 검증용 골격입니다.
실제 슬립팰 화면(눈 + 케어 문장)은 이 위에 새로 얹습니다.
Web Bluetooth는 **HTTPS 필수**라 로컬 파일로 열면 동작하지 않습니다.

## 오늘 밤 남은 것

- [ ] **골판지 몸통 2개** — 도면대로. 40분 + 15분. *현장에서는 자를 수도 붙일 수도 없습니다*
- [ ] **트레이싱지 확보** — 없으면 수면등이 아니라 손전등이 됩니다
- [ ] **라이브러리 설치 + 컴파일 검증** — `BH1750`, (선택) `Adafruit MPU6050`
- [ ] **웹앱 Vercel 배포** → 폰 크롬에서 카메라 권한 + 밝기값 확인
- [ ] **오디오 백그라운드 재생 테스트** — 화면 꺼도 숨소리가 이어지는지
- [ ] **발표 첫 문장** 한 줄 써두기
- [ ] 신분증 · 노트북 충전기 · 데이터 케이블 · USB-C→HDMI 어댑터
- [ ] **10:00 정시 도착 알람** — 부품이 선착순입니다

## 내일 아침 첫 30분

1. 체크인 즉시 **BH1750 확보** (선착순, 인당 최대 2개)
2. 운영진에게 **심사 트랙이 EASY/HARD로 나뉘는지** 확인
3. 보드 2대 살리기 → `pin_finder.ino` → Blink
4. 12:20까지 **BLE 연결 확인**. 여기까지가 생명선
