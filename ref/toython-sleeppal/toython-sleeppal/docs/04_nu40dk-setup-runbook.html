OS

Phase A — 오늘 · 보드 없이

설치와 컴파일 검증

NU-40 DK는 현장에서 배부되므로 오늘은 업로드까지는 갈 수 없습니다. 대신 툴체인 설치와 컴파일 성공까지 확인해두면, 5시간짜리 해커톤에서 가장 많은 팀이 날려먹는 구간이 사라집니다.

1

Arduino IDE 2.x 설치이미 깔려 있어도 버전 확인은 하고 넘어가세요

  • arduino.cc/en/software 에서 Arduino IDE 2.x 다운로드 (이 BSP는 1.6.12 이상이면 동작하지만 2.x 권장)
  • Windows: 설치 중 나오는 드라이버 설치 프롬프트는 전부 허용합니다.
  • macOS: Arduino IDE.app을 응용 프로그램 폴더로 옮긴 뒤 실행하세요. 다운로드 폴더에서 바로 실행하면 격리 속성 때문에 툴 실행이 막히는 경우가 있습니다.
  • 실행 후 Help → About에서 버전 확인
2

NUCODE 보드매니저 URL 등록이 한 줄이 전부입니다. 오타 하나면 다음 단계가 통째로 막힙니다

File → Preferences → Additional boards manager URLs 칸에 아래 주소를 붙여넣습니다.

Arduino IDE → Settings… (⌘ ,) → Additional boards manager URLs 칸에 아래 주소를 붙여넣습니다.

Board Manager URL

https://raw.githubusercontent.com/Nucode01/Adafruit_nRF52_Arduino/refs/heads/master/package_nuduino_index.json
주의 직접 타이핑하지 말고 복사·붙여넣기 하세요. 줄바꿈이 섞여 들어가면 IDE가 조용히 무시합니다. 이미 다른 URL이 들어 있다면 쉼표로 구분해 뒤에 추가하면 됩니다.
3

BSP 설치 — NUBoards nRF52여기가 가장 오래 걸립니다. 반드시 오늘, 집 와이파이에서

  • 왼쪽 사이드바의 보드 매니저 아이콘(두 번째) 클릭, 또는 Tools → Board → Boards Manager…
  • 검색창에 NUBoards 입력
  • “NUBoards nRF52 by NUCODE”가 뜨면 최신 버전(1.0.2)을 선택하고 INSTALL
용량 주의 이 패키지는 arm-none-eabi-gcc, nrfjprog, CMSIS 툴체인을 함께 내려받아 수백 MB에 달합니다. 행사장 와이파이에 100명이 몰린 상태에서 이걸 받기 시작하면 오전을 통째로 날립니다. 오늘 끝내세요.
4

보드 선택보드가 연결돼 있지 않아도 선택은 됩니다

  • Tools → Board → NUBoards nRF52 → NU40DK nRF52840
  • 포트는 지금 비어 있는 게 정상입니다. 보드가 없으니까요.
5

컴파일 테스트 — 툴체인이 실제로 도는지오늘의 핵심. 업로드 말고 “Verify”만 누릅니다

새 스케치에 아래 코드를 붙여넣고 ✓ Verify(Ctrl/⌘ R)를 누릅니다. 업로드(→) 버튼은 아직 누르지 마세요.

blink_test.ino

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
  Serial.begin(115200);
}

void loop() {
  digitalWrite(LED_BUILTIN, HIGH);
  delay(300);
  digitalWrite(LED_BUILTIN, LOW);
  delay(300);
  Serial.println("TOYTHON ready");
}
성공 신호 하단 콘솔에 Sketch uses ... bytes 로 시작하는 메모리 사용량 요약이 뜨면 컴파일러·BSP·보드 정의가 전부 정상이라는 뜻입니다. 여기까지가 오늘의 목표선입니다.
6

내일 쓸 스케치 미리 컴파일해두기라이브러리는 처음 한 번만 느립니다. 그 한 번을 오늘로 옮깁니다

MAKER MODE로 갈 계획이라면 QWIIC 센서를 꽂자마자 주소부터 확인하게 됩니다. I2C 스캐너를 미리 만들어 컴파일까지 통과시켜 두세요.

i2c_scan.ino

#include <Wire.h>

void setup() {
  Serial.begin(115200);
  while (!Serial) delay(10);
  Wire.begin();
  Serial.println("I2C scan start");
  for (uint8_t a = 1; a < 127; a++) {
    Wire.beginTransmission(a);
    if (Wire.endTransmission() == 0) {
      Serial.print("found: 0x");
      Serial.println(a, HEX);
    }
  }
  Serial.println("scan done");
}

void loop() {}
  • BLE를 쓸 계획이면 File → Examples → Adafruit Bluefruit nRF52 Libraries 안의 bleuart 예제도 한 번 Verify 해두세요. (이 BSP는 Adafruit nRF52 코어를 기반으로 합니다)
  • OLED를 쓸 계획이면 라이브러리 매니저에서 Adafruit SSD1306 + Adafruit GFX를 오늘 설치
7

케이블과 AI 도구 점검가장 흔한 5분 낭비 두 가지

  • USB-C 데이터 케이블을 따로 챙기세요. 보드와 함께 C-C / A-C 케이블이 2개 제공되지만, 여분이 있으면 “케이블이 충전 전용이라 포트가 안 뜨는” 사고를 즉시 배제할 수 있습니다.
  • 노트북에 USB-A만 있거나 C만 있다면 어느 쪽 케이블이 맞는지 지금 확인하세요. 필요하면 젠더도.
  • 사용할 AI 코딩 도구 로그인을 지금 확인. OpenAI가 크레딧을 제공하므로 계정 상태(결제·조직·API 키)를 미리 정리해두면 좋습니다.

Phase B — 내일 11:10 · 보드 수령 직후

첫 업로드 3분 컷

Phase A를 끝냈다면 남은 건 케이블 연결과 포트 선택뿐입니다.

8

연결 → 포트 선택 → 업로드

  1. USB-C로 보드와 노트북 연결. 별도 드라이버 설치는 필요 없습니다 (TinyUSB가 BSP에 내장)
  2. Tools → Port에서 새로 생긴 COM 포트 선택
  3. Tools → Port에서 /dev/cu.usbmodem… 선택
  4. 어제 만든 blink_test.ino를 열고 → Upload
  5. 보드의 LED가 0.3초 간격으로 깜빡이면 성공. Serial Monitor를 115200으로 열면 TOYTHON ready가 흐릅니다.
9

업로드가 막히면 — 더블탭 리셋nRF52 계열의 만능 복구 동작. 이것만 기억하세요

  • RESET 버튼을 빠르게 두 번 누릅니다.
  • LED가 천천히 맥박처럼 밝아졌다 어두워지면 부트로더 모드입니다.
  • 이때 Tools → Port를 다시 열어 새로 잡힌 포트를 선택한 뒤 업로드.
  • 무한 루프가 도는 코드를 올려 보드가 먹통이 됐을 때도 이 방법으로 되살립니다.
10

16:30 마감 대비 습관코드 수정 불가 시점이 물리적으로 존재합니다

  • 16:00에 한 번 “동작하는 버전”을 저장해두세요. 마지막 30분의 욕심이 시연을 죽이는 게 해커톤의 기본 법칙입니다.
  • 16:30 이후에는 유지보수만 허용됩니다 — 케이블 재연결, 배터리 교체는 되지만 컴파일·업로드는 안 됩니다.
  • 발표는 무대에서 직접 시연입니다. 배터리로 구동되는지, 노트북 없이도 도는지 미리 확인하세요.

막혔을 때

증상원인과 해결
보드 매니저에 NUBoards가 안 뜸URL 오타 또는 줄바꿈 혼입. Preferences에서 주소를 지우고 다시 붙여넣은 뒤 IDE 재시작. 사내망·방화벽 환경이면 raw.githubusercontent.com이 막혀 있을 수 있으니 개인 네트워크에서 시도.
설치 도중 다운로드 실패nrfjprog 등 대용량 툴 내려받다 끊긴 경우. 같은 자리에서 INSTALL 재시도하면 이어받습니다. VPN을 켜뒀다면 끄고 시도.
Port 메뉴가 비어 있음① 충전 전용 케이블 → 데이터 케이블로 교체 ② 다른 USB 포트 ③ USB 허브 대신 노트북 직결 ④ RESET 더블탭.
업로드 중 timeout / 응답 없음RESET 더블탭으로 부트로더 진입 후 포트를 다시 선택하고 재업로드.
컴파일은 되는데 LED가 안 켜짐보드 선택이 다른 nRF52 보드로 되어 있을 가능성. NU40DK nRF52840인지 재확인.
Linux에서 업로드 실패업로드 도구를 별도 설치해야 합니다: pip3 install adafruit-nrfutil --user (Windows·macOS는 BSP에 포함되어 불필요). 포트 권한은 sudo usermod -aG dialout $USER 후 재로그인.
macOS에서 실행이 차단됨시스템 설정 → 개인정보 보호 및 보안 하단의 “확인 없이 허용”을 눌러 통과시킵니다.
